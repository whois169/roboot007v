## 一、底盘 ESP32 ↔ 树莓派

### 1. 台阶测距（4 个 VL53L1X：前保险杠 2 个、后格栅 2 个，都斜着往下 30° 看地面）

**底盘自己做，不等大脑：**

| 看到什么 | 怎么判断 | 底盘怎么做 |
|---|---|---|
| **地面没了**（楼梯往下、桌子边） | 测到的距离比"平地应该测到的"远 4 cm 以上，或者测不到地面 | **马上刹车**（4 m/s²，和急停一样快，但不断电）；那个方向**锁住**，只能往反方向走；报 `CLIFF` |
| **前面有个坎**（门槛、台阶往上） | 测到的距离比平地近 3 cm 以上 | 自动限速到 0.3 m/s（仿真里过 15 mm 门槛要这么慢）；报 `STEP`，带估算高度 |
| 测距板坏了 / 没回应 | 0.5 秒没读数 | 限速 0.2 m/s；报 `STEP_SENSOR` |

- 只看**走的方向**：往前走看前面两个，往后退看后面两个。
- "平地应该测到多远"：站着的时候按几何算好；到货以后在平地上标定一次（大脑发 `{"calib":"step"}`，底盘记住当前读数当平地）。
- **大脑不能关掉这个保护**（没有"关闭台阶检测"的指令）。要下台阶以后再说，那是以后的功能。
- 锁住以后怎么解：往反方向退开 10 cm 以上、读数回到平地，自动解锁。

⚠ **盲区**：左右两边没有台阶测距。所以**横着走（麦轮左右平移）限速 0.2 m/s**，靠激光雷达看旁边有没有东西；横着走时下面有没有台阶看不到，这个要你知道。

**新增的格式：**

```
状态（原来每 0.1 秒那条 chassis，加两个字段）：
  "step":[812, 806, 795, 801]     前左、前右、后左、后右，测到的距离 mm；坏了的写 null
  "cliff":null                     锁住的方向："front" / "rear" / null

提醒（ev = warn，新加 3 个 code）：
  {"ev":"warn","code":"CLIFF","where":"front","text":"前面地面没了，已刹车"}
  {"ev":"warn","code":"STEP","where":"front","h":15,"text":"前面有 15 mm 的坎，限速 0.3"}
  {"ev":"warn","code":"STEP_SENSOR","where":"rear_left","text":"后左台阶测距没回应"}

move 做不完的原因（done 里的 why，新加 1 个）：
  "CLIFF"   走到一半发现地面没了，停下了

指令（新加 1 条，要带 id，只能在站着、停稳时做）：
  {"calib":"step","id":9}          在平地上标定台阶测距
```

### 2. 机身的灯（归底盘 ESP32 管）

**灯大部分自己按状态亮，不用大脑管：**

| 灯 | 平时 | 刹车 / 倒车 | 电量低 | 急停 / 故障 | 充电中 |
|---|---|---|---|---|---|
| 两侧腰线灯带（青） | 常亮；走的时候亮一点 | — | 变橙色 | 红色闪 | 绿色呼吸 |
| 两盏尾灯（红） | 暗红常亮 | 刹车全亮；倒车闪 | — | 红色闪 | — |
| 电机端面光环 ×4（青） | 电机通电就亮 | — | — | 灭（电机断电了） | — |
| 前面两盏白灯 | **大脑控制**（夜里、深度相机要补光时开） | | | | |

**新增的格式：**

```
指令：
  {"light":{"front":60}}          前面白灯亮度 0–100（0 = 关）
  {"light":{"dim":30}}            所有灯的总亮度 0–100（晚上调暗；默认 100）

状态（chassis 里加）：
  "light":{"front":60,"dim":100}
  "chg":true                       正在充电（INA226 测到电流是往电池里流的）
```

⚠ **要你定的一处：麦轮轮毂盖上的青色光环**。轮毂盖跟着轮子一起转，线没法接上去（要加滑环，又贵又容易坏）。我的建议：**这个光环不发光**，做成深色装饰圈；"轮子在动"让电机端面的光环来表示（它不转，线顺着电机线走）。

⚠ **灯的型号还没选**。建议全部用 **WS2812B 一类的可编程灯珠 / 灯带**（5V，一根信号线就能控制颜色和亮度），这样上面那张表的颜色变化都能做到。定了我再出灯的采购清单和接线。

## 二、头部传感器 ESP32 ↔ 树莓派

### 3. 抬头低头舵机（STS3215）

```
指令：
  {"servo":{"pitch":-20,"speed":60}}     头转到 -20°（负 = 抬头），速度 60°/秒（可省，默认 60）
                                          范围 -35（抬到最高）到 +20（低到最低），超出范围的指令丢掉并报错
  {"servo":{"relax":true}}               松开（不出力，可以用手掰）

事件：
  {"ev":"servo","pitch":-19.8,"moving":false,"load":12,"temp":38}   到位、开始动、停下时各发一次，平时每秒一次
                                          load 负载 %，temp 舵机温度 °C
  {"ev":"error","code":"SERVO","text":"..."}   卡住（负载一直 > 80%）、过热（> 65°C）、没回应 → 自己松开再报
```

- **趴下之前**大脑先把头转到 +15°（折叠位置），转到了才让底盘趴下；不然头会碰甲板。
- 模型的 **look 技能**：上 / 下 = 舵机真的抬头、低头；左 / 右 = 底盘原地转 20°（再配合屏幕上眼睛往那边看）。趴着的时候不转身，只动眼睛。

### 4. 声音（麦克风 ×2、喇叭）—— 不走 JSON

头部 ESP32 插在 USB 上同时是**两样东西**：

| 是什么 | 树莓派看到的 | 用来干什么 |
|---|---|---|
| 串口 | `/dev/ttyACM*` | 和原来一样，一行一条 JSON（传感器、红外、舵机……） |
| **USB 声卡**，名字叫 `007V-HEAD` | 一个普通的麦克风 + 喇叭 | 麦克风：16 kHz、16 位、双声道（左右两个麦）；喇叭：48 kHz、16 位、单声道 |

- 大脑那边**不用改程序**，在 `config.yaml` 里把麦克风和喇叭选成 `007V-HEAD` 就行。
- 两个麦克风先当一个用；以后可以用左右的时间差判断声音从哪边来（转头看说话的人）。

### 5. 下巴测距（VL53L5CX，8×8 个点）

原来只发一个"最近距离"。防撞要知道**在哪个位置近**（地上的矮东西、正前方的人），所以加一个整幅数据：

```
指令：
  {"tof":{"hz":5}}                每秒发几次整幅距离（0 = 不发，最多 10）
事件：
  {"ev":"tof","mm":[64 个数]}     8 行 × 8 列，从左上开始，单位 mm；没测到写 0
```

### 6. 头上的光环（转轴那圈青色）

```
指令：
  {"ring":"on"}  /  {"ring":"breath"}  /  {"ring":"off"}     常亮 / 呼吸 / 关
```
大脑按状态发：醒着常亮、待机呼吸、休眠关。

## 三、树莓派自己做的防撞（不走协议，写在这里说明一下逻辑）

激光雷达（LD19）直接插在树莓派上，用厂家自己的数据格式，大脑程序直接读。

| 走的方向上最近的东西 | 怎么做 |
|---|---|
| 大于 1 米 | 不管 |
| 0.25–1 米 | 越近限速越低（`limit`，最低 0.05 m/s） |
| 小于 0.25 米 | 发 `stop` |
| 雷达 0.5 秒没数据、车在走 | 限速 0.2 m/s，屏幕和日志里提醒 |

- 用雷达 + 下巴测距一起判断（雷达看不到比它低的东西，下巴测距补上）。
- 这一层**不经过大模型**。大脑程序如果卡死，心跳就停了，底盘 2 秒后自己停（原来就有）。
