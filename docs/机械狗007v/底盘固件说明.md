# 底盘 ESP32-S3 固件说明（机械狗007v）

> 2026-10-24 第一版。代码在 `007v/firmware/chassis/`（PlatformIO + Arduino）。
> 逻辑部分是把测过的 Python 底盘程序（`007v/chassis/controller.py`，仿真测试 47 项全过）**一行行翻成 C++**，没有另起炉灶。

## 一、文件

| 文件 | 干什么 |
|---|---|
| `src/params.h` | 所有常数（速度、加速度、台阶阈值、几何尺寸）。**自动生成**：`python 007v/firmware/chassis/gen_params.py`，数字和 Python 那边永远一样 |
| `src/controller.*` | 底盘程序：走路、站起来趴下、急停、台阶刹车、载重估计、灯。不碰硬件，对着 Python 同名函数翻 |
| `src/protocol.*` | 解析大脑发来的一行 JSON（规则和 `chassis/protocol.py` 一样严）、把事件和状态写成一行 |
| `src/hw.*` | 硬件：CAN 控制 4 个轮子、PWM 控制 4 个髋、I2C 读 AS5600 / VL53L1X / INA226、急停、灯 |
| `src/board.h` | 引脚（和 `wiring.py` 的引脚表一致）和硬件常数；标 **[到货]** 的要实物到了再填 |
| `src/main.cpp` | 主循环：每 5 ms 收指令 → 读传感器 → 算一步 → 发给电机 → 回事件和状态 |

## 二、怎么跑起来

- **I2C 单独一个任务**（核心 0）：4 个 AS5600 每 5 ms 读一次，4 个台阶测距各 50 Hz，电池每 0.1 秒。控制循环（核心 1，200 Hz）只拿最新值，不会被 I2C 卡住。
- **轮子**：SteadyWin GDZ34 驱动的"自定义 CAN 协议 V3.07"（厂家资料在 `ref/gim4310/gdz_docs/`）。1 Mbps；每 5 ms 给 4 个电机发速度（0xC1，单位 0.01 RPM），回复里带实际转速；每 10 ms 轮流问一个电机的电流（0xA4，算载重用）。站起来、趴下的过程中发 0xCF 松开轮子。驱动报故障或 100 ms 没回应 → 停车报 `WHEEL_FAULT` / `WHEEL_LOST`。
- **髋**：AS5600 量角度，BTS7960 驱动蜗轮电机。位置环 + 速度前馈；到位以后断开 PWM（蜗轮自锁，不耗电）。急停、故障时 BTS7960 使能拉低。
- **看门狗**：主循环 1 秒没动静就重启；重启时先让 4 个轮子松开。
- **急停按钮**：常闭触点直接断电机继电器（硬件，不靠程序）；常开触点给 ESP32，程序进急停状态、报 `ESTOP_BTN`。

## 四、到货以后要做的（按顺序）

1. **改电机地址**：4 个 GDZ34 出厂地址都是 1。用 USB 转 RS485 + 厂家上位机改成 前左 1、前右 2、后左 3、后右 4（或者下单时请卖家改好）。
2. **轮子转速单位**：发 60 RPM，看轮子是不是 1 秒转 1 圈；是转子转速的话把 `board.h` 的 `WHEEL_RPM_PER_RPM` 改成 10。
3. **轮子方向**：drive 0.1 m/s，四个轮子都往前转才对；反了改 `WHEEL_DIR`。
4. **髋角度零点**：车趴平、停稳，大脑发 `{"calib":"hip","id":1}`，存进 Flash（只做一次）。
5. **髋方向**：摆臂往下摆角度要变大（不对改 `HIP_SIGN`）；正占空比让角度变大（不对改 `HIP_PWM_SIGN`）。
6. **髋位置环**：先空载、再带载调 `HIP_KP`、`HIP_KV`，站起来、趴下要稳、不抖、不过冲。
7. **台阶测距标定**：站在平地上、停稳，发 `{"calib":"step","id":2}`。
8. **电池**：量分流电阻阻值填 `INA_SHUNT_OHM`；插上充电器状态里 `chg` 要是 true（不是就改 `INA_CUR_SIGN`）。
9. **灯**：灯珠型号定了以后，把每段的颗数填进 `LED_WAIST` 等（现在都是 0，不点灯）。
10. 载重标定、电池曲线：见 `底盘程序说明.md`。

## 五、还没做的（硬件接了，程序以后加）

- 髋驱动的电流检测（IS 脚）：要实测电流和电压的比例才能写过流保护。现在靠"髋跟不上 15° 超过 1 秒就停"保护。
- 蜗轮电机的霍尔编码器：现在角度和速度都用 AS5600，编码器先不用。

## 六、怎么确认 C++ 和 Python 算的一样

```bash
python 007v/firmware/chassis/test/compare.py
```

1. 在 MuJoCo 仿真里让 Python 底盘程序跑一长串动作（约 37 秒）：趴着标定髋零点、趴着想走、站起来、开灯、往前开、刹车、走一段带转弯、限速横走、全速冲向楼梯边、退开、过门槛、测距板坏、标定台阶测距、充电、软急停、急停按钮、走着时轮子没回应、不合法的指令、断线、趴下；
2. 把每 5 ms 的传感器读数和每条指令原样喂给 C++ 版（电脑上用 zig 编译，不上板子）；
3. 逐步比较输出（髋目标、轮子转速、灯）和发给大脑的每一条消息。

**结果（2026-10-24）：7480 步、401 条消息，0 处不一样。**

对比时找出来、已经两边一起改掉的：
- 状态里台阶读数的取整：Python 的 round 是“.5 取偶数”，C++ 改成一样；
- 尾灯“刹车”“倒车”的判断：速度门槛原来是 0.02 m/s，刹车每一步正好减 0.005，会被正好碰上，单精度和双精度差一点点就一个亮一个不亮；改成 0.0213，减速度也要超过 0.05 m/s² 才算刹车；
- 计时比较加了 0.1 ms 的余量（单精度累加时间，卡在阈值上时会差一拍）。
允许的差别：载重估计按 0.5 kg 取整，卡在边界上可能差 0.5 kg。

改了 Python 底盘程序以后，要：① 跑 `gen_params.py` 更新常数；② 把同样的改动翻进 C++；③ 跑一遍这个对比，必须是 0 处不一样。
