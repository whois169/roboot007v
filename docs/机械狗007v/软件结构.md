## 一、四层

```
第 4 层  大模型（总调度）      听懂你的话 → 决定用哪几个技能 → 汇报结果
            ↑ 看"感觉板"摘要          ↓ 调用技能
第 3 层  自动反应（不经过模型）  一直盯着数据，该停就停、该提醒就提醒；断网、模型卡住也照样工作
            ↑                          ↓
第 2 层  感觉板（数据中心）      所有传感器的最新读数：值、单位、在哪、什么时候测的、可不可信
            ↑ 驱动自己往上送
第 1 层  驱动                    每个硬件一个，只管读数、执行命令
```

规矩：
1. **传感器不等人来问**，驱动读到就往感觉板送。模型想知道什么，看感觉板。
2. **安全的事不交给模型**。急停、台阶、撞东西、断线、电量保护都在第 1–3 层，离硬件越近越好。
3. **模型只拿到"技能"**。每个技能背后必须有真的驱动、真的数据，没有就不给模型（不做假功能）。
4. 每块板和大脑之间都有**心跳**，一边掉线，另一边自己进入安全状态。

| 板子 | 在哪 | 管哪些硬件 | 跟谁说话 |

## 五、查出来的问题和决定（2026-10-24 已定）

1. **麦克风和喇叭怎么接到树莓派（最重要）**
   麦克风 INMP441、功放 MAX98357A 都是接在头部 ESP32 上的，可现在头部 ESP32 和树莓派之间只有"一行一条 JSON"的串口协议，是给传感器读数用的，没设计传声音（声音是连续不断的，每秒 256 千位，硬塞进去会把传感器消息堵住，大脑这边也要自己拼声音）。两个办法：
   - **A（已定）**：头部 ESP32 用 USB 同时假装成一块"USB 声卡"。树莓派把它当普通麦克风和喇叭用，大脑程序不用改；工作量在 ESP32 固件里，硬件不用再买。
   - B：另买一个 USB 麦克风阵列 + USB 小喇叭直接插头部集线器（约 150–300 元）。简单，但已经买的麦克风和功放就用不上了，头里还要重新留位置。
2. **灯由谁控制（已定）**：机身上的灯都归底盘 ESP32（它最先知道急停、刹车、电量），头上的光环归头部 ESP32。灯的型号还没选，要先定型号。
3. **"look 看向"要真动（已定）**： 上 / 下 = 俯仰舵机真的抬头低头；左 / 右 = 底盘原地转一点（脖子没有左右转的关节）。
4. **布线图有一处旧了**：接线图上台阶测距还写着"在腿上"，实际已经挪到机身前后，要改。

## 六、写的顺序（建议）

1. 先改协议（纸面上）：底盘加台阶、灯；头部加舵机、声音走法。你看过再写。
2. 底盘 ESP32 固件：照着已经测过的 `chassis/controller.py` 翻成 C++，加台阶刹车。**最先做，因为安全都在这里。**
3. 树莓派：雷达驱动 + 防撞。
4. 头部 ESP32 固件：传感器、舵机、声音。
5. 每到一个硬件，先单独测它的驱动，测通了再接进大脑；每一步跑回归测试，不能把以前测通的弄坏。
