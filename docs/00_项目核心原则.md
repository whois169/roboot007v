# RoboDog 项目核心原则（每个版本都要对照）

> 一句话：**我们做的是"科技机械狗"，不是宠物狗，更不是"装了个音箱的机器狗"。** 每个版本、每个零件、每行代码，都要让它更能干活、更有科技感，把和音箱的差距放大，而不是缩小。
>
> v0.5 方向调整（总指挥决定）：目标从"像活的宠物"改为"有科技感、能干活的机器人"。宠物化的设定（撒娇、蹭人、累了要趴、内在情绪驱动）全部取消。

---

## 1. 音箱测试（每加一个功能都先问）
**"一个智能音箱，接上同样的云端大模型，能不能做到同样的事？"**
- 能做到：这个功能不是我们的价值，可以做，但不能当卖点，也不优先。
- 做不到：这才是我们要的，优先做，做到最好。

| 场景 | 装了音箱的狗 | 我们的狗 |
|---|---|---|
| 我出门了，家里门窗关了吗 | "我不知道。" | 巡一圈，拍照发到手机："厨房窗户开着。" |
| 屋里多少度 | 报天气预报 | 每个房间测一遍，出一张温度分布图："预报外面 20°，客厅 22°，卧室 24°。" |
| 我钥匙呢 | "我不知道。" | "下午 3 点在餐桌上看到过"，附上截图 |
| （你在公司）看看家里 | 做不到 | 手机上实时看它的画面、遥控它走过去看 |
| 把空调调到 26 度 | 只能控制智能家居 | 走到空调前面，用红外直接发遥控信号，别人家也能用 |
| 洗衣机好了、有漏水 | 什么都不做 | 传感器报警，它到现场确认，再通知你 |
| 开会 | 只能听 | 记录要点，散会后发纪要（以后加胸口投影，投到墙上） |

## 2. 拉开差距的七根支柱
1. **有身体**：用自己的传感器感知世界，并且知道自己测的是什么、在哪测的、准不准。
2. **有视角**：分清"我自己测到的"和"我查到的"。两者不一致时主动指出来，并解释原因（比如"我测的是屋里，预报说的是外面"）。
3. **有记忆**：记得看到过的东西在哪、家里的布局、主人的习惯，能拿现在和过去比。
4. **有主动性**：发现异常（门窗、漏水、温度、陌生人）就自己去确认、自己汇报。
5. **诚实**：知道自己哪里不知道，说话时标明信息来源，不编造读数。
6. **能完成任务**：大模型是**任务调度员**，负责理解任务、拆成步骤、调用工具（技能）、汇报结果。
7. **科技感可视化**：让人看得到它在干什么——屏幕 HUD 眼睛、手机 App 上的地图和数据、机身状态灯、简洁的系统汇报式语气（"扫描完成，3 个房间，1 处异常"），不撒娇。

**底线**：大模型只决定"要做什么"，不直接控制电机。走路和平衡交给训练好的步态，安全交给 MC02 里谁都绕不过去的限位。

## 3. 能去很多个家
- **每个家一张地图**，各有各的坐标原点。进门先判断"这是哪"（WiFi 名字 + 激光雷达比对），来过的直接定位，没来过的进入"新环境模式"。
- **新环境先征得同意再扫描建图**。别人家的地图和照片只存在狗身上，不上传云端；主人说删就删。
- **核心能力必须随身带**：基站、雷达贴片这些外设只在你家有，是加分项。在任何一个陌生的家里，只靠身上的传感器也要能建图、导航、找东西、测环境。
- **三层大脑自动降级**：别人家没有局域网电脑，就降级成"树莓派 + 云端"。

## 4. 对硬件的要求
- **每个传感器都要接进"感觉板"**，并且至少支撑一个"音箱做不到"的任务。说不出用途的传感器不加。
- **测环境的传感器要真的测到环境**：装在通风、远离发热件的位置，到手后要校准。反例：机身里的 NTC 测的是电池和电路板，不能拿来回答"屋里多少度"。
- **光学传感器不能挡**：热成像、测距、红外收发都要直接开孔，不能放在亚克力面罩后面（亚克力挡远红外，也会削弱测距和红外遥控）。
- **反应要快**：本地反射在 0.1 秒内（转头、眼睛、出声），云端的回答可以晚 1–3 秒，用本地反应把这段等待"藏"起来。
- **隐私开关是硬件断电**，软件绕不过去。
- **外观按《外观设计规范》做**：外壳只管好看、不承力；每块壳板能平放打印、放进 256 床。

## 5. 对软件的要求
- **感觉板**：树莓派上常驻一个程序，汇总所有传感器的最新读数，每一项都带上来源（哪台设备）、时间、位置和可信度。外部设备（基站雷达、传感器贴片）也接进来，来源字段标明是哪台设备。
- **三栏上下文**：每次调用大模型都分成【我自己测到的】【我查到的】【我的记忆】三块，不能混在一起。
- **对比规则**：系统提示词里写明，两种来源不一致时必须说出来并解释原因。
- **注意力程序**：本地一直盯着传感器，发现异常或任务相关的变化，就主动叫醒大模型。
- **长期记忆**：事件日志、地图库、看到过的物品位置、每天的小结、主人的事实和习惯，执行任务时按需调出来。
- **技能菜单（插件）**：大模型只能从菜单里点技能，参数先过安全检查。新工具按插件标准加：接进感觉板 + 注册技能 + 一句话说明。
- **大脑不绑定身体**：任务、工具、记忆这些代码不关心身体是腿还是轮子，导航只发"往哪走、走多快"。

## 7. 每个版本发布前的检查清单
- [ ] 这个版本让"音箱测试"里做不到的事变多了吗？
- [ ] 新加的硬件有没有接进感觉板？有没有对应的任务？
- [ ] 有没有哪个改动让它更像音箱或更像宠物了（比如只会被动回答、撒娇）？
- [ ] 安全底线还在吗（大模型不碰电机、硬件限位、隐私断电）？
- [ ] 外观有没有按《外观设计规范》做？新零件能不能打印、装上去？
- [ ] 设计验证全部通过了吗（干涉检查、皮带长度、仿真扭矩）？

## 8. 怎么让以后的 Claude 也记住
Claude 不会自动记得上一次聊天。**每次开新对话时，先把这个文件发给它**（或者把资料包里的这份文件贴进去），再说要做什么。本地 Claude Code 会通过项目里的 `CLAUDE.md` 自动读到它。
