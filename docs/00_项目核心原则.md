# RoboDog 项目核心原则（每个版本都要对照）

> 一句话：**我们做的不是"装了个音箱的机器狗"。** 每个版本、每个零件、每行代码，都要把这个差距放大，而不是缩小。

---

## 1. 音箱测试（每加一个功能都先问）
**"一个智能音箱，接上同样的云端大模型，能不能做到同样的事？"**
- 能做到：这个功能不是我们的价值，可以做，但不能当卖点，也不优先。
- 做不到：这才是我们要的，优先做，做到最好。

| 场景 | 装了音箱的狗 | 我们的狗 |
|---|---|---|
| 今天天气怎么样 | "今天 20°。" | "预报外面 20°，我在屋里测到 22°，比外面暖和。你出门还是加件外套。" |
| 钥匙在哪 | "我不知道。" | "我下午看到在餐桌上。" |
| 你一直坐着 | 什么都不做 | 你在沙发上坐了 2 小时没动，它过来蹭你 |
| 洗衣机停了 | 什么都不做 | 跑过来告诉你 |
| 它自己累了 | 没有"自己" | "我腿有点热，趴一会儿。" |

## 2. 拉开差距的六根支柱
1. **有身体**：用自己的传感器感知世界，并且知道自己测的是什么、在哪测的、准不准。
2. **有视角**：分清"我自己感觉到的"和"我查到的"。两者不一致时主动指出来，并解释原因（比如"我测的是屋里，预报说的是外面"）。
3. **有记忆**：记得过去发生的事、主人的习惯，能拿现在和过去比（"今天比昨天热""你这周睡得都很晚"）。
4. **有主动性**：不等你问，发现值得说的事就自己开口、自己过来。
5. **诚实**：知道自己哪里不知道，说话时标明信息来源，不编造读数。
6. **用身体表达**：情绪和意图用眼睛（屏幕）、耳朵、头的朝向、姿态、尾巴表现出来，不只靠嘴说。

**底线**：大模型只决定"想做什么"，不直接控制电机。走路和平衡交给训练好的步态，安全交给 MC02 里谁都绕不过去的限位。

## 3. 对硬件的要求
- **每个传感器都要接进"感觉板"**，并且至少支撑一个"音箱做不到"的行为。说不出用途的传感器不加。
- **测环境的传感器要真的测到环境**：装在通风、远离发热件的位置，到手后要校准。反例：机身里的 NTC 测的是电池和电路板，不能拿来回答"屋里多少度"。
- **反应要快**：本地反射在 0.1 秒内（转头、眼睛、出声），云端的回答可以晚 1–3 秒，用本地反应把这段等待"藏"起来。
- **隐私开关是硬件断电**，软件绕不过去。

## 4. 对软件的要求
- **感觉板**：树莓派上常驻一个程序，汇总所有传感器的最新读数，每一项都带上来源、时间、位置和可信度。
- **双栏上下文**：每次调用大模型都分成【我自己感觉到的】【我查到的】【我的记忆】三块，不能混在一起。
- **对比规则**：系统提示词里写明，两种来源不一致时必须说出来并解释原因。
- **注意力程序**：本地一直盯着传感器，发现异常或有意思的变化，就主动叫醒大模型。
- **长期记忆**：事件日志、每天的小结、主人的事实和习惯，聊天时按需调出来。
- **技能菜单**：大模型只能从菜单里点技能，参数先过安全检查。

## 5. 每个版本发布前的检查清单
- [ ] 这个版本让"音箱测试"里做不到的事变多了吗？
- [ ] 新加的硬件有没有接进感觉板？有没有对应的"音箱做不到"的行为？
- [ ] 有没有哪个改动让它更像音箱了（比如只会被动回答、不再用身体表达）？
- [ ] 安全底线还在吗（大模型不碰电机、硬件限位、隐私断电）？

## 6. 怎么让以后的 Claude 也记住
Claude 不会自动记得上一次聊天。**每次开新对话时，先把这个文件发给它**（或者把资料包里的这份文件贴进去），再说要做什么。这样每个新版本都会按这些原则来设计和检查。
