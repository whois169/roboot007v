# 头部通信协议（树莓派大脑 ↔ 头部两块板）

> 写固件的人看这份。大脑这边的代码：`007v/brain/dog/protocol.py`（事件检查）、`007v/brain/dog/hud.py`（屏幕指令检查和渲染）、`007v/brain/dog/eyes.py`（串口收发）。

## 怎么连
机械狗007v 头里有**两块板**，各一根 USB 线接树莓派，都走 USB 串口（CDC），波特率 115200（`007v/brain/config.yaml` → `eyes.serial`）：
- **屏幕板**（微雪 ESP32-S3-Touch-LCD-4.3B，`port`）：收屏幕指令，自己画 HUD；发屏幕触摸 `{"ev":"touch","zone":"screen",...}`、`hello`、`hb`。
- **传感器板**（旧的头部 ESP32-S3，`sensor_port`）：收红外、热成像指令；发头顶/下巴触摸、传感器读数、隐私开关、红外、热画面、`hello`、`hb`。
- 只接一根线时（`sensor_port` 留空），所有指令都发到屏幕板那根（老接法），事件格式不变。
- 两块板发的 JSON 都写成紧凑格式（没有多余空格），`ev` 放第一个字段。
- 两个方向都是**一行一条 JSON**：UTF-8 编码，`\n` 结尾，一行不超过 2048 字节（最长的是热画面，约 1.1 KB）。
- 收到看不懂、不合规的行，直接丢掉，不要卡住。大脑那边也一样，丢掉时会在日志里写原因。

## 大脑 → ESP32：屏幕指令
字段都可以省略，只发要改的部分。

```
{"mode":"track","gaze":[0.3,-0.1],"level":0.6}
{"mode":"error","text":"E-NET","hold":2.5}
{"status":{"temp":22.1,"sim":true,"bat":null,"spd":0.8,"load":6.5}}
{"log":["FACE 1 MOT 0.02"]}
```

| 字段 | 意思 |
|---|---|
| `mode` | 12 个状态之一：idle wake listen think speak track scan thermal alert error sleep low_bat |
| `gaze` | 视线 `[x, y]`，范围 -1 到 1。x = -1 是机器人自己的左边；y = -1 是上，+1 是下 |
| `level` | 0 到 1。聆听时表示麦克风音量，汇报时表示语音音量 |
| `text` | 提示文字，最多 14 个字符，换模式时自动清掉 |
| `hold` | 这个模式至少保持几秒，期间来的模式切换先排队 |
| `status` | 上下两条的状态：`temp` 温度，`sim` 是否假数据，`bat` 电量 %，`spd` 速度 m/s，`load` 载重 kg（`null` 表示不知道） |
| `log` | 往数据流里加几行，每行最多 72 个字符，只能用英文大写、数字和少量符号 |

画布是 800×440（屏幕 800×480 的 y = 20–460，上下各 20 像素藏在玻璃框后面，不画）。每个状态长什么样、画法有哪些限制，看 `007v/brain/README.md` 的第②块。固件里的渲染器照着 `hud.py` 翻成 C++ 就行（LVGL canvas 或直接画帧缓冲），字体数据可以直接拷过去。

## ESP32 → 大脑：事件
每条都带 `ev` 字段。

| 事件 | 例子 | 什么时候发 |
|---|---|---|
| hello | `{"ev":"hello","fw":"0.1.0","caps":["touch","light"]}` | 开机或重连时发一次，写明固件版本和有哪些功能 |
| hb | `{"ev":"hb","up":1234}` | 心跳，**每秒一次**；`up` = 开机多少秒。大脑 3 秒收不到，就认为头部掉线了 |
| touch | `{"ev":"touch","zone":"head","action":"tap"}` | 触摸。`zone`：head 头顶 / chin 下巴。`action`：tap 点一下 / hold 按住满 1 秒（按住时就发）/ release 按住以后松开 |
| sensor | `{"ev":"sensor","name":"light","value":120.5,"unit":"lux"}` | 传感器读数，变化明显时发，最多每秒一次 |
| privacy | `{"ev":"privacy","on":true}` | 隐私开关拨动时发一次，开机时也发一次。`on: true` = 拨到"隐私"，这时相机和麦克风已经**硬件断电** |
| error | `{"ev":"error","code":"I2C","text":"BH1750 no ack"}` | ESP32 自己出错 |

触摸的规矩：只按了一下就松开，松开时发 `tap`；按住满 1 秒，当场发 `hold`，松开时再发 `release`。

### 传感器名字（sensor 的 name）
| name | 是什么 | 单位 | 装在哪 |
|---|---|---|---|
| light | 环境光照 | lux | 头顶光照窗（BH1750） |
| distance | 前方最近物体距离 | mm | 前脸测距窗（VL53L5CX） |
| presence | 毫米波检测到有人 | true / false | 屏幕上方（LD2410） |
| presence_distance | 毫米波测到的人的距离 | cm | 屏幕上方（LD2410） |
| head_temp | 头内温度（不是屋里温度） | °C | 头壳里 |
| room_temp | 室内温度（大脑会加上校准值） | °C | 头壳后下方通风口（SHT40），离发热件 ≥30mm |
| room_humidity | 室内湿度 | % | 同上 |

要加新传感器：先在 `007v/brain/dog/protocol.py` 的 `SENSORS` 表里加一行，再更新这张表。

## 红外遥控（前脸的红外发射管 + 接收头）
固件建议用 IRremoteESP8266 库：能认出的协议就按协议收发，认不出的按原始波形收发。

**大脑 → ESP32**（单独一行，带 `ir` 字段，不和屏幕指令混在一行）：

| 指令 | 意思 |
|---|---|
| `{"ir":{"op":"learn","timeout":15}}` | 开始学：打开接收头，等遥控器按一下，最多等 timeout 秒（1–60） |
| `{"ir":{"op":"send","code":{...}}}` | 发出一个码 |
| `{"ir":{"op":"cancel"}}` | 不学了 |

**ESP32 → 大脑**：

| 事件 | 什么时候发 |
|---|---|
| `{"ev":"ir","op":"learned","code":{...}}` | 学的时候收到了一个码（收到第一个完整的码就停止学习） |
| `{"ev":"ir","op":"timeout"}` | 学的时候 timeout 秒内没收到 |
| `{"ev":"ir","op":"sent"}` | 码发完了 |
| `{"ev":"ir","op":"fail","text":"..."}` | 学或发的时候出错 |

**红外码 code 的三种写法**（大脑只存、不解读，原样交回去发）：

| 写法 | 例子 | 用在哪 |
|---|---|---|
| 协议 + 码值 | `{"proto":"NEC","bits":32,"value":"0x20DF10EF"}` | 电视、风扇、机顶盒这类，一个键一个码 |
| 协议 + 整串状态 | `{"proto":"GREE","state":"0x...."}` | 空调：每按一下都把温度、模式整串发出去 |
| 原始波形 | `{"raw":[9000,4500,560,...],"khz":38}` | 库认不出的协议：亮、灭交替的时长（微秒，1–65535，最多 1024 个），载波频率 30–60 kHz |

`proto` 用 IRremoteESP8266 里的协议名（`typeToString()` 的结果）；`value` 和 `state` 写成 `0x` 开头的 16 进制文字。

## 热成像（前脸 MLX90640，32×24 点）
**大脑 → ESP32**：`{"thermal":{"hz":1}}`：每秒发几帧给大脑（0 = 不发，最多 8）。大脑开机时发一次。

**ESP32 → 大脑**：每帧一行
```
{"ev":"thermal","w":32,"h":24,"min":21.3,"max":55.2,"px":"<base64>"}
```
- `px`：w×h 个字节，base64 编码。从左上角开始一行一行排，**第 0 列是狗自己的左边**（按传感器朝前看的方向）。
- 每个字节 0–255 表示这个点在 min 和 max 之间的位置：温度 = min + 字节 / 255 × (max − min)。
- 编码方法照 `007v/brain/dog/thermal.py` 的 `encode()` 写。

**屏幕**：屏幕板读不到热成像，THERMAL 模式用大脑转过来的帧画：屏幕切到 THERMAL 时，大脑让传感器板每秒发 4 帧，收到的 `{"ev":"thermal",...}` 原样转发给屏幕板（屏幕板收到这种行就更新热画面），切走后恢复平时的频率。只接一根线时还是板子自己画。画法照 `007v/brain/dog/hud.py` 的 `_thermal()`：热画面每点 3×2 像素、左右镜像，最热点画角标，左边写 MAX / MIN，右边画色标。色标按温度的平方根分配，有很烫的东西时，人也还看得清。

## 大脑收到事件后做什么
- **摸头顶（tap）**：平时是唤醒并确认，马上响提示音、屏幕闪 `[ONLINE]`、开始听，不用看着它，也不用喊唤醒词。如果它正在想或正在说，就马上停下来听你说。
- **摸下巴（tap）**：它在想或在说时，停下来待机；它在听时，不听了。
- **长按**：暂时只记一笔，以后再定用途。
- **隐私开关打开**：不听、不看、不主动说，屏幕显示 `PRIVACY`；拨回来恢复。
- **热画面**：分析出热源（温度、方向、猜是什么）和冷点，放进感觉板；60°C 以上持续 5 秒会主动提醒（详见 `007v/brain/README.md` 第⑨块）。
- **红外学到了 / 超时 / 出错**：存进码库并汇报，或者告诉用户没学到（详见 `007v/brain/README.md` 第⑧块）。
- **传感器读数**：放进感觉板，大模型回答时能看到，比如"头顶光照 120 lux（来源：头部 ESP32 传感器）"。

## 在电脑上模拟（没有 ESP32 时）
HUD 模拟器窗口里用键盘代替：**T = 摸头顶，C = 摸下巴**（按住 1 秒以上 = 长按），**P = 拨隐私开关**，**R = 学红外时按了一下遥控器**（模拟器会编一个 NEC 码），**H = 打开 / 关掉假灶台**（模拟器的热画面是一个假房间），**[ ] = 调屋里温度、, . = 调湿度**（模拟器每 5 秒发一次 room_temp、room_humidity）。模拟器收到发码指令，会回一个 `sent`。按键产生的事件也是先变成一行 JSON 文字，再走和真串口一样的解析和检查。
