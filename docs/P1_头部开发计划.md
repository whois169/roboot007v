# P1 头部开发计划 + 大脑软件架构 v0

> 总指挥定的方向。本地 Claude Code 照这份文档开发；改方向前先问总指挥。
> 所有设计都要过《项目核心原则》的"音箱测试"：音箱做得到的不算本事。
> v0.5 更新：项目方向改成"科技机械狗"（不是宠物狗）。眼睛改成科技风 HUD；完成标志去掉宠物化动作；头部新增 MLX90640 热成像和红外遥控收发；前脸加银色面板 + 黑色传感器面板。

## 0. 目标
桌上一个能干活的机器狗头：
- 能听、能说、能看，屏幕上是科技风 HUD 眼睛，被摸会唤醒并确认。
- 有"自己的视角"：分得清自己测到的和网上查到的。
- 发现值得汇报的事会主动开口，说话简洁、像系统汇报。

**完成标志**：录一段 1–2 分钟的演示视频，里面至少有 3 个"音箱做不到"的瞬间。比如：
- 有人走进来，它眼睛切到 TRACK 锁定目标，并主动汇报"检测到 1 人"。
- 摸它的头，眼睛快闪显示 ONLINE，唤醒并确认。
- 问它温度，它说"预报 20°，我测到屋里 22°"。
- 说"把空调调到 26 度"，它用红外发射管发出遥控信号（先用电视或风扇的遥控器学习、演示）。
- 切到热成像模式，屏幕显示伪彩色画面，指出哪里有发热的东西。

|---|---|---|---|

| 第三批（v0.5 新增） | **红外发射管 940nm + 红外接收头 VS1838B**（几块钱）、**MLX90640 热成像**（看预算，一两百元） | 控制空调电视；黑暗中找人、发现发热电器 | 红外收发现在就买；热成像预算够就买，不够先按官方尺寸留位置 |

**新决定：SHT40 温湿度传感器提前到第二批买**（约 10 元，I2C）。原因：它是演示"有自己视角"最直接的一个例子，即"预报说多少度，我测到多少度"。

## 2. 软件架构（运行在树莓派上，Python）

```
brain/
  main.py          启动所有模块（asyncio）
  config.yaml      参数；API 密钥放 .env，不进 git
  senses/          感觉板：所有传感器读数汇总在这里
    board.py         每条读数带：值、单位、来源、位置、时间、可信度
    camera.py        USB 相机：本地人脸 / 人体检测（OpenCV，YuNet 之类的轻量模型）
    audio_in.py      麦克风：本地唤醒词（sherpa-onnx）、音量、声音事件
    esp32.py         和头部 ESP32 串口通信（第二批硬件到了再接）
    environment.py   SHT40 温湿度、BH1750 光照（到货再接）
    thermal.py       MLX90640 热成像（32×24，I2C 接 ESP32，原始温度矩阵发给树莓派）
    ir_remote.py     红外收发：学习遥控器、按名字发码（"空调-26度"），码库存进记忆
  attention.py     注意力：盯着感觉板，发现值得说的事就叫醒大脑
  mind/
    llm.py           大模型适配层：统一接口，可以换不同厂家（等 ChatGPT 调研结果再选默认厂家）
    prompt.py        拼提示词：人设 + 三栏上下文
    memory.py        记忆：SQLite，事件日志 + 每日小结 + 主人的事实
    tools.py         查天气等"查到的"信息
  body/
    skills.py        技能菜单：大模型只能点菜单里的技能，参数先过检查
    voice.py         说话：TTS → 扬声器
    eyes.py          眼睛 HUD 指令（JSON，发给 ESP32；没有屏幕时先在电脑窗口里按 284×76 模拟）
```

### 2.1 三栏上下文（核心，必须做）
每次调用大模型都分三块：
```
【我自己感觉到的】（我身上的传感器，标了时间和位置）
【我查到的】（网上的资料，可能不准）
【我的记忆】（和这次相关的过去的事）
```
系统提示词写明：两种来源不一致时，必须说出来并解释原因。例如"我测的是屋里，预报说的是外面"。

### 2.2 延迟策略
- **0.1 秒内本地先反应**：听到唤醒词或被摸，马上出声"嗯？"、眼睛变化、看向声音方向。
- **云端回答 1–3 秒后到**：流式输出，第一句话一到就开始说。
- **画面不推流**：只在有事时截一张图（512px，约 100KB）。比如有人出现、有人叫它、被摸、发呆超过 30 秒。

### 2.3 隐私
- 隐私开关是硬件断电。软件读开关状态：关了就不采集、不上传。
- 只有本地唤醒词触发后才往云端传音频。

### 2.4 技能菜单（P1 版）
`说话(内容)`、`眼睛(模式, 持续)`、`看向(方向)`（P1 没有脖子，先只用眼睛看）、`记住(事实)`、`安静一会儿(分钟)`、`红外发码(设备, 指令)`、`红外学习(设备, 指令)`、`热成像(开/关)`。

### 2.5 眼睛：科技风 HUD（v0.5）
- 2.25 寸 ST7789 长条屏，284×76。深色背景，主色青色 #5CE1FF，警告琥珀色，报警红色。
- 眼睛是两块**切角方块**（和机身的斜切角设计语言一致），用来表示看哪里；下面一条细扫描线，四角有角标。不要卡通圆眼。
- 状态：IDLE 待机（呼吸光 + 偶尔扫描）、WAKE 唤醒确认（快闪 + ONLINE）、LISTEN 聆听（音量条）、THINK 思考（变窄 + 进度）、SPEAK 汇报（声波）、TRACK 锁定目标（准星框跟脸）、SCAN 扫描、THERMAL 热成像伪彩色、ALERT 警告、ERROR 错误、SLEEP 休眠、LOW_BAT 低电量。每种都要有过渡动画。
- 指令统一 JSON，例如 `{"mode":"track","gaze":[0.3,-0.1],"level":0.6}`：现在发给笔记本上的模拟器，以后原样通过串口发给 ESP32。
- 模拟器只用 ESP32 画得出来的图元（线、矩形、圆、简单渐变、位图字体），目标 30 帧。
大模型输出 JSON 点技能，`skills.py` 检查参数合法再执行。

## 3. 里程碑（按顺序做，每个都有验收标准）

| 里程碑 | 内容 | 验收标准 | 需要的硬件 |
|---|---|---|---|
| **M1 对话闭环** | 唤醒词 → 识别 → 大模型 → 说出来 | 说完话到它开口 < 2.5 秒；连续聊 10 轮不出错 | 树莓派 + 第一批 |
| **M2 会看** | 本地检测到人 → 截图 → 大模型看图 | 你走进画面，它主动说话，而且说得出你在干什么 | 同上 |
| **M3 有视角、有记忆** | 感觉板 + 三栏上下文 + 记忆 + 注意力 | 问温度能说出"预报多少、我测多少"（没有 SHT40 前先用假数据测逻辑）；能记住你说过的一件事，第二天还记得 | 同上 |
| **M4 头部电子** | ESP32-S3：HUD 眼睛、触摸、麦克风、隐私开关、热成像、红外收发；串口协议 | HUD 有 10 种以上状态且有过渡动画；摸头唤醒并显示 ONLINE；能学习一个遥控器按键并发出去 | 第二、三批 |
| **M5 装进头壳** | 打印头壳 + 桌面底座，装好，录演示视频 | 达到第 0 节的完成标志 | 全部 |

## 4. 打印（现在就能做的）
1. **先打孔径测试片**：让本地 Claude Code 生成一块测试片，Φ3 / Φ4 / Φ5 / Φ8 / Φ19 孔各一个，再加 M3、M4 热熔螺母孔各一个。打出来量好，结果记进《零件尺寸收集清单》。
2. **桌面底座（新零件）**：P1 没有脖子电机，要一个底座把头立在桌上。要求：
   - 接头部框架的俯仰轴位置，可以手动调抬头、低头的角度，用一颗 M5 螺丝锁住。
   - 底座里留走线空间（1 根 USB + 1 对电源线），接树莓派。
   - 底座稳，头不会往前栽。
   - 风格按机身的方正、斜角来，和狗身体的设计语言一致。
3. **头壳等长条屏、分体相机尺寸确认后再打**，先按确认后的尺寸改模型。v0.5 头壳前面多了两个件：银色前脸面板（PETG 银色）和黑色传感器面板（PETG 哑光黑），配色按《外观设计规范》。
4. **SHT40 放在头里**：位置要通风，离 ESP32、功放、屏幕至少 30mm，推荐放在头壳后下方的敞口附近，到货后和准的温度计对比做校准。
5. **热成像和红外收发直接开孔**：亚克力挡远红外，也会削弱测距和红外遥控，所以它们都开在黑色传感器面板上，不放在面罩后面。屏幕下面那条只有约 11mm 净高，MLX90640 要选小转接板，或者把 TO-39 探头单独焊在 12×10mm 的小板上（到货后按实物改模型）。
