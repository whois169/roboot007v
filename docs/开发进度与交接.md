## 一、用户的工作习惯和定下的规矩（一定要遵守）
- **说中文，用简单直白的中文**写文档和回复。
- **测试说明按语音模式写**（`python main.py`）：用户 2026-10-12 说以后基本不用打字模式。
- **用 git**（从 v0.6 起工程是 git 仓库，只在本地，没有远程仓库）。做完一块、用户测通后提交一次；`brain/.env`（密钥）、`brain/models/`、`brain/data/` 不进 git。改完必须跑回归测试（见下）。
- **一块一块做**：每做完一块就停下，告诉用户怎么运行、怎么测，用户测通了再做下一块；做完写进对应的 README。
- **要装大依赖或要做选择时先问用户**；小事按推荐做法直接做，事后说明。
- **改完 CAD 设计**要跑 `CLAUDE.md` 里的验证流程，并同步完整资料包（最新是 v0.6 资料包，01–08 编号文件夹）、README 版本记录、相关文档。
- **定位：科技机械狗**，不是宠物狗，也不做 AI 音箱（见核心原则）。语气是系统汇报式，不说“汪”，不叫“主人”。
- **不用唤醒词**：看着它说话就行，唤醒词只留作备用。
- **隐私**：用户说“不管隐私了”，看着它说的话会发给大模型。**例外**：总指挥要求以后的“会议助手”开始记录前必须先征得在场的人同意。
- **模型以后再换**：现在 DeepSeek 只是测试用；回答速度、合成音色、看图模型，用户说以后自己找了再改，不要卡在这上面。
- **树莓派性能测试**：用户说以后自己弄。
- **上位机是树莓派 5**（2026-10-12 用户更正，不是 4B）。供电要单独一路 5V 5A，GPIO 供电要开 `usb_max_current_enable=1`，见 `docs/电子系统与接线.md`。CAD 里占位盒的名字还叫“树莓派4B”，下次改 CAD 重新生成时顺手改名。

## 五、在这台电脑上干活的技术坑
- 系统 Python 3.11，命令用 `python`，不是 `python3`。
- **工程路径里有中文**：有些 C++ 库打不开中文路径。`brain/main.py` 启动时会先切到 `brain/` 目录，用相对路径（`dog/config.py` 的 `rel()`）；MuJoCo 脚本也是先 `os.chdir` 再加载。写文本文件一律加 `encoding="utf-8"`。
- 在 Bash 里用 heredoc 写 Python 补丁时，`\n` 这类转义经常被吃掉，改出语法错误。**多行改动用 Edit 工具，或者先把补丁脚本写成文件再运行。**
- 用 `sed` 批量替换要小心范围：曾经一条 sed 改到了别的同名代码行，导致“大模型回答第二句就报错”，靠回归测试才发现。
- **语音合成服务**在桌面 `C:\Users\67309\Desktop\RoboDog_TTS`（不在工程里，自己的 .venv，显卡版 PyTorch 2.14 cu126）。依赖版本被 `constraints.txt` 锁住：transformers 必须 5.15.1（5.19 会报 MimiConfig 没有 rope_theta）。0.6B 模型**不支持 instruct 语气说明**（官方代码里写死了），硬给会生成乱声音。跑大脑和测试前先开服务（start.bat）。
