## 安装（第一次）

需要 Python 3.11。在 `brain` 文件夹里运行：

```bash
pip install -r requirements.txt
python scripts/download_models.py
```

第二条会下载本地模型（唤醒词、说话检测、语音识别、人脸检测和识别），放在 `007v/brain/models/`。网络断了再运行一次，会接着下。

**说话的声音由单独的“语音合成服务”提供**，在桌面的 `RoboDog_TTS` 文件夹里（Qwen3-TTS，跑在笔记本显卡上），说明见那个文件夹里的 `README.md`。**运行大脑之前，先双击 `RoboDog_TTS\start.bat` 把服务开起来**；服务没开时大脑照样能运行，只是不出声（话会打印在控制台）。

然后把 `.env.example` 复制一份，改名为 `.env`，在里面填上大模型的密钥。没有密钥也能跑，会自动用假回答。

**树莓派上**还要先装声卡库：`sudo apt install libportaudio2`。

## 运行

```bash
python main.py            # 语音模式：看着它直接说话（不用唤醒词；备用唤醒词“你好小狗”）
python main.py --text     # 文字模式：打字跟它说话（不用麦克风，最适合先测大模型和语音合成）
python main.py --mock     # 用假回答，不调用大模型、不花钱
python main.py --devices  # 列出麦克风和扬声器（选设备时用）
python main.py --eyes     # 只开 HUD 模拟器，12 个状态循环演示
python main.py --see      # 摄像头调试：画面 + 人脸框，HUD 锁定目标
python main.py --debug    # 多打印一些日志（每段用时、每句话为什么理或不理）
python main.py --memory   # 看它记住了什么（事实、最近的事件、每日小结）
python tests/run_tests.py # 一键回归测试（改完代码跑一遍，确认没改坏）
```

按 `Ctrl+C` 退出，或者直接关掉 HUD 窗口。

## 第①块：语音对话（不用唤醒词，看着它说话就行）

### 怎么叫它
**不用喊唤醒词。走到它面前、看着它，直接开口就行。**
1. **走进画面**：屏幕上眼睛从数据流里拼出来，准星框锁定你（TRACK）。
2. **看着它**（脸够近、正对着它、持续 1 秒）：屏幕切到聆听（LISTEN），音量条亮起来，数据流里出现 `ATTN FACE LOCK`，表示“我在听”。
3. **直接说话**：说完停顿 0.8 秒自动收声 → 本地识别 → 大模型 → 边想边说。
4. **还看着它**：回答完继续听，可以接着聊；你扭头或走开了，还有 6 秒可以接着说。
5. **没开口就扭头、走开超过 1.5 秒**：停止聆听，回到锁定或待机。

**唤醒词“你好小狗”留着当备用**：它看不见你的时候（另一个房间、背对着它）喊一声还能叫到它，会马上响两声提示音、屏幕显示 ONLINE。`config.yaml` 里 `listen.wake_word: false` 可以完全关掉。

### 怎么少误触发（五道关卡）
看着它说话难免会误触发，比如你看着它、其实在跟旁边的人说话。所以叠了五道关卡：
1. **要真的在看它**：脸要够近（至少占画面宽度 12%）、正对着它（看鼻子是不是在两眼中间），并且连续 1 秒。只是路过、侧着脸都不算。
2. **说话时一直看着它**：说话期间至少 60% 的时间脸是正对它的。说着说着扭头跟别人说，就不理。
3. **太短、只是语气词不理**：说话不到 0.5 秒、识别出来不到 2 个字，或者只是“嗯、啊、好的、对、哈哈……”。
4. **大模型再判断一次**：提示词里会写明这次是“看着我说话（没喊唤醒词）”触发的。只有明显是在问它、叫它、让它做事才回答；像在跟别人聊天、打电话、自言自语、念东西，或者拿不准，就输出 `{"skill":"ignore"}` 不说话。实测 8 句全判断对了：问温度、让它扫描、问它看不看得见我 → 回答；“老婆今天晚上吃什么啊”“喂张总那个合同我下午发你”、念合同条款、“哎呀这个怎么又坏了”“那你明天几点到” → 不理。
5. **扭头就停**：没开口就扭头或走开超过 1.5 秒，停止聆听。

不理的时候数据流里会出现原因：`IGN SHORT`（太短）、`IGN NOT FACING`（说话时没看着它）、`IGN FILLER`（语气词）、`IGN NOT FOR ME`（大模型判断不是对它说的）。

还是可能误触发，比如电视里的人正对着镜头说话。关卡的严格程度都在 `config.yaml` 的 `listen` 里，调严了误触发更少，但也更难叫到它。

### 后面的流程
- **识别**：用本地 SenseVoice 把声音转成文字，录音不出电脑。
- **想**：把文字发给大模型。大模型只能输出“技能”（见下面），一行一个，边生成边执行。
- **说**：每收到一句话，马上找语音合成服务要声音，边收边播：第一段一般 0.4 秒内到，再攒 0.3 秒就开始播。后面几句同时去要，服务那边排队合成，句子之间没有空档。

它自己说话的时候不听麦克风，免得把自己的声音当成别人说的话。所以说话中途不能打断它，以后头部的 ESP32 有回声消除了再加“插话”。

### 技能菜单
大模型不能直接控制任何东西，只能输出下面这几种 JSON。执行前检查参数，不合规的那一行直接丢掉，日志里会写原因。

| 技能 | 例子 | 现在的效果 |
|---|---|---|
| 说话 | `{"skill":"say","text":"收到。外部温度 22 度，晴。"}` | 合成后播放 |
| 屏幕模式 | `{"skill":"display","mode":"scan"}` | 切到扫描 / 热成像 / 警告 / 待机，至少显示 6 秒 |
| 看向 | `{"skill":"look","direction":"left"}` | 视线往那边移 3 秒再回来（以后还会转脖子） |
| 记住 | `{"skill":"remember","fact":"钥匙放在餐桌上"}` | 存进长期记忆，重启也记得（一次只记一件事） |
| 忘掉 | `{"skill":"forget","fact":"钥匙放在门口鞋柜上"}` | 把那条记忆标记为不用了 |
| 安静一会儿 | `{"skill":"quiet","minutes":30}` | 记下时间（第⑥块“主动开口”会遵守） |
| 不回答 | `{"skill":"ignore"}` | 这句不是对它说的，什么都不说（只在“看着我说话”触发时用） |

### 怎么测
1. **先测文字模式**：`python main.py --text`
   - 问“你是谁”：应该用人设里的名字回答，句子短。
   - 说“我叫××，记住”，再问“我叫什么”：应该答对，日志里有“记住了”。
   - 问“屋里多少度”：应该说明屋里读数是假数据，**不能编数字**。
2. **再测语音模式**：`python main.py`
   - 坐到摄像头前看着它 1 秒：日志出现“你在看着我，开始听”，屏幕切到聆听。
   - 直接问一句话，不喊唤醒词，等它回答。
   - 看着它但跟旁边的人说话，或者打个电话：应该不理，数据流里出现 `IGN ...`。
   - 扭头看别处说话：不应该进入聆听。
   - 背对它喊“你好小狗”：备用唤醒词还能叫到它。
3. **测假回答**：`python main.py --mock`，不花钱，看流程对不对。
4. 加 `--debug` 能看到每一句为什么被理或不理。

### 调参数（`config.yaml`）
- 老是叫不到它：`listen.near_face_width` 调小（离远一点也算）、`listen.facing_min` 调小（侧一点也算）、`listen.attend_seconds` 调短。
- 老是误触发：反过来调，或者把 `listen.attention_ratio` 调大。
- 你话没说完它就开始回答：把 `listen.end_silence_seconds` 调大（比如 1.2）。
- 备用唤醒词不灵：把 `wake.threshold` 调小（比如 0.15），或者把 `wake.boost` 调大；老是误唤醒就反过来调。
- 换合成引擎：`tts.engine` 改成 `local`（本地，快）或 `edge`（微软，音色好但国内慢）。
- 音色、机械感：改桌面 `RoboDog_TTS\config.json` 的 `default_speaker`、`effect`（也可以在这里的 `tts.speaker`、`tts.effect` 临时指定）。
- 改唤醒后的那句话：改 `react.ack_text`，改完删掉 `data/cache/` 让它重新合成。
- 换大模型厂家：改 `llm.base_url` 和 `llm.model`，再换 `.env` 里的密钥，配置文件里有各家的地址。
- 改名字、性格：改 `persona`。

### 现在的速度（笔记本实测）
- 唤醒词到响提示音：几毫秒（本地生成）。
- 识别一句话：约 0.05–0.2 秒。
- 大模型第一句话：1.5–2.5 秒（DeepSeek）。
- 语音合成服务拿到第一段声音：约 0.4 秒（Qwen3-TTS，笔记本 RTX 3060），再缓冲 0.3 秒开始播。
- **从你说完到它开口：大约 2.3–2.7 秒**，现在大头是大模型。
- 搬到树莓派 5 以后，语音合成还是在笔记本上做，树莓派通过家里的 Wi-Fi 去要，多一点网络时间。

### 隐私
- 你决定不再考虑隐私限制：看着它说的话都会识别成文字发给大模型。
- 声音本身只在本机识别，不上传；它要说的话也只发给自己笔记本上的语音合成服务，不出家门。

## 第②块：眼睛（宽屏 HUD，科技风格）

运行任何模式都会打开一个 **HUD 模拟器**窗口，模拟机械狗007v 头上的屏幕（微雪 ESP32-S3-Touch-LCD-4.3B，800×480）。前脸玻璃窗是 118×50 mm 的长条，屏幕亮的区域约 95×50 mm，上下各约 20 像素藏在框后面，所以只画中间 **800×440**，窗口里就是 1:1 的真实像素（笔记本屏小可以把 `eyes.sim.scale` 改成 0.75）。字是放大的位图字体，带一点像素感是故意的，和屏幕板上画出来一模一样。（2026-10-17 从旧的 2.25 寸 284×76 长条屏改过来，玩法和 12 个状态都没变。）

### 设计思路：平时是数据流，有人打交道时眼睛才出现
- **平时**：全屏是**真实的数据流**，每一行都是大脑推过来的真读数和事件（见下面）。用 4×5 小字体放大 2 倍，整屏文字一直平滑地往上流：新的一行从底下冒出来、逐字打出，越往上越暗，到顶淡出。进来的数据多就流得快一点，没有新数据就慢慢停住，不编假内容。
- **有人和它打交道时**（被叫醒、聆听、思考、汇报、锁定目标）：数据流里的方块往中间飞，0.6 秒“拼”出两只眼睛，拼好时闪一下；数据流退到后面变得很淡。
- **结束后**（人走了、对话结束回到待机）：眼睛“解体”成方块，0.5 秒散回数据流。
- 眼睛出现本身就是一个信号：**它在注意你**。眼睛跟着视线移动，表示它在看哪里。
- 深色背景，主色青色 `#00E5FF`，警告和低电量用琥珀色，错误用红色。眼睛是带切角的方块，和机身的斜切角一致。
- 四个角有角标。**上面一条**：左边当前模式（大字），中间 `007V`，右边电池图标和电量（现在测不到，显示 `--%`）。**下面一条**：左边提示文字或追踪坐标，右边速度 `SPD`、背上载重 `LOAD`、温度 `T`（带 `*` 表示假数据），底部有刻度尺。背景有很淡的点阵。文字都用英文缩写和数字。眼睛外面有一圈发光（往外画几圈越来越暗的框，不用透明，屏幕板上照样能画）。

### 数据流里滚的是什么（全是真的）
| 什么时候 | 例子 |
|---|---|
| 开机自检 | `BOOT 007V BRAIN`、`TTS QWEN3 OK`（服务没开时是 `TTS OFFLINE`）、`CAM OK FACE YUNET`、`KWS OK ASR SENSEVOICE`、`WX OUT 22.2C RH74 CLOUDY`、`LLM DEEPSEEK-CHAT READY` |
| 每 1 秒一行读数（轮流） | `T22.0* H55* SND -64DB`（`*` = 假数据）、`FACE 1 MOT 0.02`、`13:11:44 UP 3M STATE IDLE`，约每 30 秒一行天气 |
| 事件 | `EVT PERSON IN`、`EVT PERSON OUT`、`KWS WAKE` |
| 每段耗时 | `ASR 9CH 0.05S`（识别了几个字、多久）、`LLM 1ST 1.92S`（大模型第一句多久）、`RESP 2.31S`（从说完到开口多久） |
| 大模型的动作 | `CMD DISPLAY SCAN`、`CMD LOOK LEFT`、`MEM +1 FACT`、`QUIET 30M` |
| 出错 | `LLM ERR APITIMEOUTERROR` |

字不大（字高约 1.2 毫米），一米外看不清内容，只看得到数据在流；凑近看，每一行都说得出意思。数据流的速度靠大脑每秒推一行读数撑着（`eyes.status_seconds`），实测 93% 的时间都在流动。

### 12 个状态（切换时都有过渡动画，不硬切）
| 状态 | 样子 | 什么时候出现 |
|---|---|---|
| IDLE 待机 | **没有眼睛**，全屏数据流往上流，偶尔一道竖线从左扫到右 | 平时、没人 |
| WAKE 唤醒确认 | 眼睛拼出来、闪白一下，弯成两道 ∩（打招呼，照效果图），下面 `[ONLINE]`，保持 0.9 秒 | 听到唤醒词、摸头顶、点屏幕 |
| LISTEN 聆听 | 两个发光的圆角方块眼睛（效果图那样）+ 眼睛下面 9 根音量条，跟着麦克风音量跳 | 唤醒后、回答完等你接着说时 |
| THINK 思考 | 眼睛变窄，中间 3 个方块轮流亮，眼睛下面有进度条来回跑 | 识别完、等大模型的时候 |
| SPEAK 汇报 | 眼睛 + 眼睛下面的声波，振幅跟着合成语音的音量变 | 播放回答时 |
| TRACK 锁定目标 | 眼睛变成准星框（四角框 + 十字），锁定时框从大缩到合适大小，跟着人脸移动，左下角显示坐标 | 闲着时看到人 |
| SCAN 扫描 | 没有眼睛，扫描线来回扫，淡网格，下面显示 `SWEEP xx%` | 大模型调用 `display` 技能 |
| THERMAL 热成像 | 没有眼睛，中间是热画面（最热点框出来），左边最高、最低温度，右边色标。模拟数据标 SIM（见第⑨块） | 大模型调用 `display` 技能 |
| ALERT 警告 | 琥珀色“凶”眼睛（上沿往鼻子那边斜，照效果图），数据流**卡住不动**，眼睛下面闪烁的警告三角 + 原因，底部移动的斜纹 | 大模型调用 `display` 技能；以后接报警 |
| ERROR 错误 | 红色，数据流卡住，中间提示框：`ERR` 闪烁 + 错误码 | 大模型连不上时（`E-NET`），保持 2.5 秒 |
| SLEEP 休眠 | 数据流停了，只剩一条很暗的线和一个慢慢闪的光标 | 以后：休眠时 |
| LOW_BAT 低电量 | 琥珀色，中间提示框：电池图标闪烁 + 电量 | 以后：电量低时 |

看图：`data/hud_shots/` 里每个状态一张截图（还有“拼合中”和“解体中”各一张），`overview.png` 是总览，`demo.gif` 是从开机到休眠的完整演示。重新生成：`python scripts/hud_capture.py`。

### 统一指令（原样发给屏幕板）
大脑只发 JSON 指令，一条一行，字段都可以省略、只发要改的部分：
```
{"mode":"track","gaze":[0.3,-0.1],"level":0.6}
{"mode":"error","text":"E-NET","hold":2.5}
{"status":{"temp":22.1,"sim":true,"bat":null,"spd":0.8,"load":6.5}}
{"log":["FACE 1 MOT 0.02"]}
{"level":0.42}
```
| 字段 | 意思 |
|---|---|
| `mode` | 12 个状态之一：idle wake listen think speak track scan thermal alert error sleep low_bat。眼睛出不出现由模式决定 |
| `gaze` | 视线 `[x, y]`，-1 到 1。x 按机器人自己的方向：-1 是它的左边（你面对屏幕时眼睛往你的右边移），y：-1 上、+1 下 |
| `level` | 0–1。聆听时是麦克风音量，汇报时是语音音量 |
| `text` | 提示文字（警告原因、错误码等，最多 14 个字符），换模式时自动清掉 |
| `hold` | 这个模式至少保持几秒，期间来的模式切换先排队，到时间再切（唤醒默认 0.9 秒） |
| `face` | 表情（可省略）：`normal` 圆角方块、`happy` 弯弯的 ∩、`angry` 上沿斜切；换模式时回到那个模式默认的表情 |
| `status` | 上下两条的状态：`temp` 温度、`sim` 是否假数据、`bat` 电量 %、`spd` 速度 m/s、`load` 背上载重 kg（`null` 表示不知道；速度和载重等底盘程序接上再发） |
| `log` | 往数据流里加一行或几行，每行最多 62 个字符，只能用英文大写、数字和 `- . % : / * = < > ( ) , # [ ] ? !` |

模拟器收到的是“先变成一行 JSON 文字、再解析回来”的指令，和以后串口上走的字节完全一样。换真屏幕时只要把 `config.yaml` 里 `eyes.type` 改成 `serial`，`port` 填屏幕板的串口、`sensor_port` 填头里传感器板的串口（两块板各一根 USB；只接一根时留空），大脑代码一行不用改。不合规的指令发出去之前就会被拦下，日志里会写原因。

### 能移植到 ESP32 的画法
渲染器（`dog/hud.py`）只通过一个画图接口出图，只用这几样：**点、线、矩形、实心凸多边形、圆、5×7 位图字体**，ESP32 的 TFT_eSPI 库都有对应函数。
- 数据流是 4×5 小位图字（状态文字是 5×7 位图字）；眼睛拼合、解体就是 3×3 的小方块在移动，都是 ESP32 画得动的东西。
- 没有透明混合、模糊、发光着色器。“淡入淡出”都是把颜色往背景色缩放来做的。
- 所有动画只看“现在的时间”，目标 30 帧（笔记本上画一帧约 11 毫秒）。
- 以后写 ESP32 固件时，把 `hud.py` 的渲染器照着翻成 C++ 就行，字体数据可以直接拷过去。

### 自动切换（已接进大脑）
- 开机 → 数据流逐行打出真实的初始化过程。
- 闲着时看到人 → 眼睛拼出来变成准星框（TRACK）跟着你；人走 1.5 秒后解体回到数据流。
- 看着它 1 秒 → 直接进 LISTEN；喊备用唤醒词 → WAKE（拼出眼睛 + ONLINE）→ 0.9 秒后进 LISTEN。
- 说完 → THINK → 开始说话 → SPEAK → 回答完回到 LISTEN（可以接着说）或 IDLE（眼睛解体）。
- 在聆听、思考、汇报时视线也跟着你，但屏幕模式不会被锁定目标抢走。
- 大模型连不上 → ERROR，显示 `E-NET`。
- 大模型可以用 `display` 技能切 SCAN / THERMAL / ALERT（至少显示 6 秒）、用 `look` 技能看向某个方向。

### 怎么测
1. `python main.py --eyes`：12 个状态每个 3 秒循环播放（数据流里推的是 `DEMO MODE ...` 演示说明，不是真读数）。
2. 在模拟器窗口里按键手动试：`1`–`9`、`0`、`-`、`=` 依次切换 12 个状态，方向键移动视线，`Q`/`A` 调音量，`Esc` 退出。
3. `python main.py --text` 或 `python main.py`：看开机自检、平时的数据流；走到摄像头前看眼睛拼出来锁定你，走开看它解体；叫醒它完整走一遍聆听 → 思考 → 汇报。
4. 加 `--debug`，控制台里能看到每一行推给屏幕的内容（`[屏幕] ...`）。

## 第③块：看

### 本地一直在看（画面不出电脑）
- **人脸检测**（OpenCV 自带的 YuNet 模型）：每秒 5 次，一次约 3 毫秒。知道有几个人、在左边还是右边、离得远近。
- **动静检测**：前后两帧比一比，知道画面里有东西在动。分不出是不是人，所以告诉大模型时标“可信度低”。
- **眼睛跟着人看**：人在左边，眼睛就往左边看。只在狗闲着的时候跟，说话和想事情时眼睛听大模型的。
- OpenCV 5 去掉了以前的人体检测器，所以现在“有人”是靠看到人脸判断的。人背对着、离得太远时测不到。以后要认人的身体，可以加一个几 MB 的小检测模型。

### 只在有事时截图
三种情况会截一张 512px 的图（约 15KB）交给看图模型，平时不上传：
1. **有人出现**：之前 10 秒都没看到人脸，现在看到了。
2. **有人叫它**：听到唤醒词（文字模式下是你发消息）。截图和你说话同时进行，等你说完，看图结果一般也回来了；最多再等 1 秒，等不到就先回答。
3. **发呆太久**：10 分钟没有互动，截一张看看周围。

看图模型说的话会放进【我自己感觉到的】，标明“哪个时间、因为什么拍的、可能看错”。

**现在还没配看图模型**（DeepSeek 看不了图），所以截图不上传，大模型只拿到本地检测结果。想配的话，在 `config.yaml` 的 `vision.model` 里填好地址和模型名，再在 `.env` 里加一行 `VISION_API_KEY=你的密钥`，三项都填了才会上传。

### 大模型拿到的是什么样子
```
【我自己感觉到的】
- 摄像头（头部前方）：现在画面里有 1 张人脸，最近的一个在我左前方、离我比较远（本地人脸检测，0 秒前，可信度高）
- 摄像头（头部前方）：画面里有东西在动（本地动静检测，0 秒前；只说明有东西在动，不一定是人，可信度低）
- 看图（头部前方，3 秒前因为「有人叫我」拍的一张照片，看图模型的描述，可能看错，可信度中）：……
```

### 怎么测
1. `python main.py --see`：会开两个窗口，一个是摄像头画面（带绿色人脸框），一个是眼睛。
   - 走出画面 10 秒再回来：日志出现“有人出现了”。
   - 在摄像头前左右移动：眼睛跟着你看（你往你的右边走，眼睛也往你的右边看）。
   - 在画面窗口里按 `s`：没配看图模型时，会打印大模型现在能拿到的信息。按 `q` 关掉画面窗口。
2. `python main.py --text`，问“你看得见我吗”“我在哪边”：它应该照着检测结果回答。问“我穿什么颜色”：没配看图模型时，它应该说看不出来，**不能编**。
3. 摄像头被别的程序占着，或者不想开：`config.yaml` 里 `vision.enabled: false`。这时它会说自己看不见。

## 第④块：感觉板 + 三栏上下文 + 查天气

### 感觉板
所有传感器的最新读数都汇总在一起，每一条都带：**值、来源、位置、时间、可信度**，有的还带一句说明。现在板子上有：

| 读数 | 来源 | 说明 |
|---|---|---|
| 看到的人 | 本地人脸检测 | 第③块 |
| 画面动静 | 本地动静检测 | 可信度低：不一定是人 |
| 看图描述 | 看图模型 | 配了看图模型才有 |
| 周围声音 | 麦克风音量 | 只在语音模式有；只算音量，不录音；自己说话时不算 |
| 室内温度、湿度 | 头部 SHT40（第⑩块） | 现在是模拟器假装发的，可信度标“无（假数据）” |
| 现在时间、开机多久 | 自己的时钟 | |

超过一定时间没更新的读数会标“已经过期，可能不准了”。

温湿度由头部 ESP32 的 SHT40 发过来（见第⑩块）。不开 HUD 模拟器时，可以把 `senses.temp_hum` 改成 `fake`，用大脑自己编的假数据。

### 我查到的：天气
- 用 Open-Meteo，免费，不用注册，也不用密钥。城市在 `config.yaml` 的 `weather.city` 里改，**现在填的是成都**，改成你那里。
- 启动时查一次，之后每 30 分钟在后台刷新，聊天时直接用，不增加等待时间。
- 只有你的话里带“天气、冷、热、穿、伞、下雨……”这些词时，才把天气放进【我查到的】，免得每句话都扯天气。词表在 `weather.keywords` 里。

### 三栏上下文
每次问大模型，你的话前面都会附上三栏：
```
【我自己感觉到的】
- 室内温度：22 °C｜来源：温湿度传感器（还没装，现在是假数据）｜位置：屋里（模拟）｜时间：1 秒前｜可信度：无（假数据）
- 看到的人：1 张人脸，最近的一个在我正前方，离我不远｜来源：本地人脸检测｜位置：头部前方摄像头｜时间：0 秒前｜可信度：高
……
【我查到的】
- 外面现在：晴，19.2 °C（体感 20.4 °C），湿度 83%｜来源：Open-Meteo 天气预报｜位置：四川成都，室外｜查询时间：0 分钟前
- 今天预报：毛毛雨，16–24.3 °C，降水概率 51%｜……
【我的记忆】
（第⑤块做）
【主人说】
今天要穿外套吗？
```
系统提示词里写明了：两种来源不一致时必须说出来，并解释原因（“我测的是屋里，预报说的是外面”）；假数据要说明是假的；和话题无关的读数不用提。

### 实测（DeepSeek）
- “今天要穿外套吗？屋里冷不冷？” → 先说屋里 22 度是假数据，再说查到外面 19 度、今天有毛毛雨，建议穿外套、带伞。
- “屋里比外面暖和吗？” → 说屋里读数是假的，能信的只有外面 19.2 度，所以不知道屋里暖不暖。不会拿假数据硬比。
- “现在几点了”“你好呀” → 正常回答，不扯温度。

### 怎么测
1. `python main.py --text --debug`：每句话都会把发给大模型的三栏完整打印出来，看看内容对不对。
2. 问“要带伞吗”“屋里冷吗”“外面多少度”，看它分不分得清屋里和外面、会不会说明假数据。
3. 问几句和天气无关的话，看它会不会乱扯温度。
4. 改温度试试：把 `senses.fake_temp` 改成 30，再问“屋里热吗”。它应该说读数是 30 度，但同时说明这是假数据。

## 第⑤块：记忆

### 存在哪
- `007v/brain/data/memory/` 文件夹里，**每个家一个 SQLite 数据库文件**。现在在哪个家由 `config.yaml` 的 `memory.home` 决定，默认是 `home_main`，对应文件 `data/memory/home_main.db`。
- 去别人家时把 `memory.home` 改成别的名字（比如 `home_parents`），两边的记忆完全分开、不会串。以后做“进门识别”时，会自动切换。
- 删掉某个家的 `.db` 文件，就是把那个家的记忆全部清掉；复制整个 `data/memory/` 文件夹就是备份。

### 存什么
| 类型 | 是什么 | 怎么来的 |
|---|---|---|
| 事实 | 你告诉它的事：名字、习惯、东西放在哪、约定 | 大模型用 `remember` 记下，一次一件；用 `forget` 忘掉 |
| 事件 | 什么时间发生了什么 | 每轮对话（你说了什么、它答了什么）、有人出现/离开、看图描述，自动记 |
| 每日小结 | 前一天发生了什么，2–4 句话 | 启动时和之后每小时检查一次，前几天还没小结的就让大模型写；连不上大模型就写次数统计 |

### 怎么用起来
每次回答前，按你这句话的字词挑出相关的记忆，放进提示词的【我的记忆】：
- 相关的**事实**（最多 6 条，带记下的时间）；
- 最近 7 天里相关的**事件**；你问到“刚才、今天、昨天、上次、有人……”时，再带上最近发生的事；
- **昨天的小结**，以及和这句话相关的其他小结。

规则：以“你告诉它的事实”为准，对话记录只是当时的经过、可能过时；东西换了地方，它会先忘掉旧的再记新的；没记过的就说没有记录，不编。

### 实测（DeepSeek，中间“重启”了一次）
- “记一下，我叫阿峰，我的钥匙放在门口鞋柜上” → 分成两条记：`用户叫阿峰`、`钥匙放在门口鞋柜上`。
- “钥匙我换地方了，现在放在餐桌上” → 忘掉鞋柜那条，记下餐桌，名字那条不受影响。
- 重启后问“我钥匙放哪了” → “记录显示钥匙在餐桌上，今天 14:47 记下。”
- “我的手机放哪了” → “没有记录。手机的位置我没记过。”
- “那个出门时间不用记了，忘了吧” → 只删掉出门时间那一条。

### 怎么测
1. `python main.py --text`：告诉它几件事，按 `Ctrl+C` 退出，再重新运行，问它刚才说的事。
2. `python main.py --memory`：看数据库里现在存了什么。
3. 告诉它东西换地方了，再用 `--memory` 看旧的那条是不是没了。

## 第⑥块：主动开口

### 它什么时候会自己开口
| 情况 | 什么时候说 | 说什么（大模型根据感觉板、天气、记忆决定） |
|---|---|---|
| **今天第一次见到你** | 你走到它面前、看着它的那一刻 | 今日要紧的事：比如今天会不会下雨、要不要带伞、你交代过的事 |
| **你回来了** | 离开 5 分钟以上又回来，走到它面前看着它时 | 同上，只挑有用的说 |
| **你坐太久了** | 摄像头连续 60 分钟一直看到你 | 直接提醒你起来活动 |

- 前两种说完会直接进入聆听，你可以接着跟它聊。
- 真正说什么由大模型决定：不寒暄、不自我介绍、不问“有什么可以帮你”；不值得说就一个字都不说。
- 实测（DeepSeek，记忆里有“每天早上七点出门”）：
  - 回来了 → “你回来了。现在 22:26，明早七点出门，建议现在准备休息。”
  - 坐太久 → “你已连续坐 75 分钟，建议起身活动 5 分钟。”

### 不会话太多（都在 `config.yaml` 的 `attention` 里）
- 两次主动开口至少隔 **10 分钟**，每小时最多 **3 次**；
- 同一类事有自己的冷却时间（回来了 30 分钟、今日播报 12 小时、久坐 60 分钟）；
- 夜里 **23 点到早上 7 点**不主动说；
- 你让它“安静一会儿”期间不说（`quiet` 技能）。

每次主动开口（包括大模型决定不说的）都会写进决策日志，数据流里显示 `ATTN ARRIVE` / `ATTN FIRST` / `ATTN SIT`。

只在语音模式、开了摄像头时才有（文字模式没有）。以后接上毫米波、温度这些传感器，再加“发现异常主动汇报”这类情况。

### 顺带修的
- 合成时“%”和“22:14”里的冒号容易念错（会把“降水概率 59%”念成“五十九”，意思就错了）。现在送去合成前先转成“百分之59”“22点14分”，“°C”转成“度”，“km/h”转成“公里每小时”。

### 怎么测
- `python main.py`，离开摄像头 5 分钟以上再回来，走到它面前看着它：它会先开口，说完进入聆听。
- 早上第一次坐到它面前：会有一句今日播报。
- 想快点测“回来了”和“坐太久”，把 `attention.arrive_after_minutes` 改成 1、`attention.sitting_minutes` 改成 2，`min_gap_minutes` 改成 1（测完改回来）。

## 第⑦块：摸头唤醒 + 头部通信协议

头部的板子（屏幕板发屏幕触摸；传感器板发触摸、传感器读数、隐私开关）会通过 USB 串口，把事件和心跳发给大脑，每条是一行 JSON。完整格式见 `../../docs/头部通信协议.md`，写 ESP32 固件时照着写。

**摸头顶**：唤醒并确认。马上响提示音，屏幕闪 `[ONLINE]`，然后开始听。不用看着它，也不用喊唤醒词，适合你在旁边干活、没正对着它的时候。
它正在想或正在说时摸头顶，会马上停下来听你说（这是现在唯一能打断它的办法）。

**摸下巴**：它在说话时，停下来待机；它在听时，不听了。

**隐私开关**：拨到“隐私”，它就不听、不看、不主动说，屏幕显示 `PRIVACY`。真硬件上，相机和麦克风会直接断电。

**传感器读数**：光照、测距、毫米波这些读数会进感觉板。大模型能看到每个读数的来源和位置，比如“头顶光照窗（BH1750）”。

**心跳**：ESP32 每秒发一次心跳，大脑 3 秒收不到就在日志里报“可能掉线了”。只有接真 ESP32 时才检查，模拟器不查。

### 现在怎么测（没有 ESP32，用键盘代替）
`python main.py`，在 HUD 窗口里按：
- **T** = 摸头顶：应该听到“嘀”一声，屏幕闪 `[ONLINE]`，然后不用看着它直接说话，它会回答；
- 它说话时按 **T**：马上停下，转去听你说；
- 它说话时按 **C**（摸下巴）：马上停下，回到待机；
- **P**：拨隐私开关，屏幕变成 `PRIVACY`，这时看着它说话它不理；再按一次恢复；
- 按住 **T** 超过 1 秒：长按，现在只在数据流里记一行 `TOUCH HEAD HOLD`。

键盘产生的事件和真串口走的是同一条路：先变成一行 JSON 文字，再解析、检查。

## 第⑧块：红外遥控

它能学你家遥控器的按键，以后你说一句，它就用红外帮你开关家电。这是音箱做不到的：音箱只能控制联网的智能家电，它能控制家里任何一台用红外遥控器的老空调、老电视、风扇。

**学按键**：说“学一下电视的开关”。
1. 它先回答“请把遥控器对准我的前脸，按一下开关键。”；
2. 屏幕切到 SCAN，中间显示 `IR LEARN`，开始等信号，最多等 15 秒（`config.yaml` → `ir.learn_seconds`）；
3. 收到信号后响一声，回答“已学会：电视 开关。”；15 秒内没收到，就说“没有收到红外信号，学习已取消”。
等的时候摸一下头顶，就不学了，转去听你说话。同一个按键再学一次，会覆盖旧的。

**用**：说“把电视打开”“空调关了”“电视声音大一点”。
- 大模型能看到已经学过哪些按键。说法不一样也能对上，比如“关掉”“关机”都算“关”，“空调”也能找到“客厅空调”。
- 它会回答“已发送：电视 开关。”。红外是单向的，它不知道电视到底开没开，所以只说“已发送”，不说“已经开好了”。
- 没学过的按键不会乱发，它会说还没学过，问你要不要现在学。

**忘掉**：说“把电视的遥控都忘了”，或者“忘掉空调的制冷26”。

**空调要注意**：空调遥控器每按一下，都会把温度、模式整串发过去，所以“开”学到的是你按下那一刻的设定。要不同温度，就分开学，比如“学一下空调的制冷26”“学一下空调的制热22”。

**存在哪**：和记忆放在同一个文件 `data/memory/<家>.db` 里（`ir_codes` 表）。去别人家时换了 `memory.home`，码库也跟着换。

### 现在怎么测（还没有红外管，用模拟器）
`python main.py`（或 `python main.py --text` 打字测），然后：
1. 说“学一下电视的开关”，等它说完、屏幕出现 `IR LEARN`；
2. 在 HUD 窗口按 **R**，就当是拿遥控器对着它按了一下，它会说“已学会：电视 开关”；
3. 说“把电视打开”，它说“已发送”。控制台里能看到“[模拟红外] 发出：……”；
4. 再试一次学按键，这次不按 R，15 秒后它会说没收到；
5. 说“把风扇打开”（没学过），它应该说还没学过，不会乱发。

**红外管到了以后**：ESP32 固件用 IRremoteESP8266 库，按 `../../docs/头部通信协议.md` 的红外部分收发，大脑这边不用改。注意红外要**对着家电**才有效，射程一般几米。以后脖子能转了，再加“先转头对准家电再发”。

## 第⑨块：热成像

头上的热成像模块（MLX90640）能看到 32×24 个点的温度，看得见人、热水、电器、灶台、冷窗户。这也是音箱做不到的。

**它怎么用热成像**
- 头部 ESP32 每秒发一帧热画面给大脑（`config.yaml` → `thermal.hz`）。大脑找出最热、最冷的地方，把比周围高 4 度以上的一片圈成“热源”，算出它在哪个方向，再按温度猜是什么：28–40°C、个头大的像人；40–60°C 像热水、电器；60°C 以上像灶台、取暖器。
- 分析结果放在感觉板上。你问“看看哪里热”“前面有没有热的东西”，它先把屏幕切到热成像，再汇报“最热在右前方约 16° 偏下，52 度，可能是热水”。
- 热成像测的是**物体表面温度**，不是室温。问室温时，它会用温湿度传感器的读数，不拿热成像回答。

**屏幕**：THERMAL 模式中间是热画面，最热点用角标框出来；左边是最高、最低温度，右边是色标。画面左右镜像，像照镜子：在它左边的东西，你看到在右边。用模拟数据时左下角标 `SIM`。

**高温主动提醒**（安全提醒）：画面里有 60°C 以上的点、持续 5 秒，它会主动开口。屏幕先闪 ALERT `HOT 95C`，然后说“右前方约 18 度检测到高温点，95.7 度，可能是灶台或电热水壶，请去确认是否忘了关火”。同一处高温 10 分钟内只提醒一次；温度降下来以后再热起来，会重新提醒。安静模式下也会说，隐私开关打开时不说。温度、时间都在 `config.yaml` 的 `thermal` 里改。

### 现在怎么测（还没有模块，用模拟器的假房间）
HUD 模拟器里有一个假房间：左上角一扇冷窗户（17.5°C），右下角一杯热水（52°C），一个人在画面里慢慢走来走去（30 秒一个来回）。
1. `python main.py --text`，打字“看看前面哪里最热”：屏幕切到热成像，它报出热水杯的温度和方向，并说明这是模拟数据；
2. 打字“前面有人吗”：它应该说前面有一个像人的热源，在哪个方向；
3. 在 HUD 窗口按 **H**，打开假灶台（90°C 以上）。等 5 秒，它会主动提醒高温；再按一次 H 关掉。

**模块到了以后**：ESP32 固件读 MLX90640，按 `../../docs/头部通信协议.md` 的热成像部分发帧，大脑这边不用改。画面左右反了，就把 `thermal.mirror` 改成 `true`；买的是 110° 广角版，就把 `thermal.fov` 改成 `[110, 75]`。

## 第⑩块：室内外对比 + 屋里舒不舒服

P1 视频里的亮点：“预报外面 18 度，屋里我测到 24.3 度，比外面高 6.3 度”。音箱只能念天气预报，它能说出自己测到的。

**屋里的温湿度从哪来**：头部的 SHT40，由 ESP32 读出来发给大脑（`config.yaml` → `senses.temp_hum: head`）。SHT40 装在头里，会比屋里略热，到货后拿一个准的温度计对比，差多少就填进 `senses.temp_offset`。

**对比由程序算好**：聊到温度、温差、外面、屋里、开窗、空调这类话题时，【我查到的】里除了天气，还会附上一行算好的对比，比如“屋里 24.3 °C（我自己测的），外面现在 18 °C（预报的实况），屋里比外面高 6.3 度；湿度 屋里 55%、外面 70%”。大模型直接用这些数，不自己算，所以不会算错。屋里或外面的数缺一个，就不给对比，不会编。

**屋里不舒服就主动提醒**（`config.yaml` → `comfort`）：
- 屋里 ≥ 28 °C 偏热、≤ 16 °C 偏冷、湿度 ≥ 75% 偏潮、≤ 30% 偏干，**持续 10 分钟**，而且摄像头看到有人，它会主动开口；
- 它先报屋里的读数和外面的天气，再给一个建议：外面凉快就建议开窗；外面也不行就建议开空调或加湿、除湿；
- 如果已经学会了空调的遥控按键，它会问“要我开空调制冷 26 度吗？”，**只问，不会自己发**。你说“开吧”，它才发；
- 2 小时提醒一次；夜里、你让它安静时、隐私开关打开时都不说。

### 怎么测（用语音，`python main.py`）
模拟器假装有 SHT40：屋里一开始是 24°C、55%。在 HUD 窗口按 **[ ]** 键调温度（每次 1 度），按 **, .** 键调湿度（每次 5%）。屏幕右上角的温度会跟着变。
1. 看着它问：“屋里和外面温差多少？”它会说出屋里、外面的温度和差值，并说明屋里的读数是模拟的；
2. 按 6 下 **]**，把屋里调到 30 度，再问“屋里热不热”，它会说偏热，并给出建议；
3. 测主动提醒：把 `config.yaml` 里 `comfort.minutes` 临时改成 `1`，重新运行，按 6 下 **]**，坐在摄像头前等 1 分钟多一点。它会主动说屋里偏热，建议开窗。如果你之前教过它空调的按键，它还会问要不要开空调。
   如果刚开机它已经跟你打过招呼，要再等 10 分钟才会说，因为两次主动开口至少隔 10 分钟（`attention.min_gap_minutes`）。测完记得把 `comfort.minutes` 改回 `10`。

## 第⑪块：认人

它能认出登记过的人，叫出名字；看到没登记过的人，会主动汇报。

**怎么认**：摄像头每秒给面前够近、够正的脸算两次“脸部特征”（OpenCV 的 SFace 模型，本地运行，约 37MB，下载脚本里已经加上了）。特征是 128 个数字，和登记过的人比，像到一定程度（`vision.match_threshold`，默认 0.42）才算认出。最近 5 次里有 3 次是同一个人才定下来，免得一帧认错就叫错名字。
**只存数字，不存照片**，和记忆放在同一个文件 `data/memory/<家>.db` 里（`people`、`faces` 两张表）。

**登记**：看着它说“记住我，我叫阿峰”，或者“这是我妈妈，记住她”。
1. 它先说“请正对我，离近一点，保持几秒”；
2. 屏幕切到 SCAN，中间显示 `FACE SCAN`，看着面前**最近的那张脸**收集 5 组特征（最多 8 秒）；
3. 成功会响一声，说“已登记：阿峰，用户本人”。没看清就说“没有看清脸，登记取消”。
- 关系分四种：用户本人、家人、朋友、访客。
- 同一个人再登记一次是**补充**，换个光线、角度多登记几次，会认得更准。
- 这张脸已经登记成别人了，它会说“这张脸已经登记过，是××”，不会重复登记。
- 删掉：说“把××删掉”或“忘了××”。

**认出以后**：感觉板上“看到的人”会写“认出是 阿峰（用户本人）”。主动打招呼、回答问题时它知道是谁；问它“你知道我是谁吗”，它能说出名字。还没认清时，它不会乱猜。

**陌生人**：认定面前是没登记过的人，它会主动汇报“发现一名未登记人员，在我左前方”。如果旁边同时认出了你，它会问要不要登记这位。30 分钟最多汇报一次（`attention.cooldown_minutes.stranger`），夜里不说。
一个人都没登记时，谁都算“陌生人”，所以这时候不报，只在感觉板上写“还没有登记过任何人”。

### 怎么测（`python main.py`）
1. 坐到摄像头前，看着它说：“记住我，我叫××。”等它说完“请正对我”，保持正对几秒，它说“已登记”；
2. 离开几秒再回来，看着它问：“你知道我是谁吗？”它应该说出你的名字；
3. 找家人或朋友站到摄像头前（你先登记好自己），它会主动汇报发现未登记人员，并问你要不要登记；
4. 说“记住他，他叫××”，让对方正对它，登记好以后，它就认得了；
5. 老是认错人，就把 `vision.match_threshold` 调高一点（比如 0.5）；老是认不出你，就多登记几次，或者调低一点（不要低于 0.363）。

## 防止听到自己的声音
不用唤醒词以后，它说完话、你还看着它，就会直接进入聆听，扬声器的余音可能被当成你说的话。现在有三道防线：
1. 自己说话时，以及说完后 0.6 秒内，不听麦克风（`audio.mute_tail_seconds`）。
2. **回声识别**：识别出来的话，如果和它自己 30 秒内说过的某句话大部分重合，就当成回声不理（数据流里显示 `IGN ECHO`）。按拼音比，不看声调，数字先统一成中文读法，所以识别把“二十二度天气晴”听成“22度填气情”也能认出来。
3. 大模型最后再判断一次是不是对它说的。

## 决策日志（用来调参数）
每句话理没理、为什么，都会写一行到 `data/logs/decisions-日期.jsonl`。只记文字，不录音。例子：
```
{"time": "2026-10-08 14:20:31", "decision": "answer", "via": "look", "seconds": 1.8, "looked": 0.92, "text": "帮我扫描一下客厅。", "reply": ["收到，正在扫描客厅。"], "resp_seconds": 2.41}
{"time": "2026-10-08 14:21:05", "decision": "ignore", "via": "look", "seconds": 2.3, "looked": 0.35, "reason": "NOT FACING", "why": "说话时只有 35% 的时间看着我", "text": ""}
```
- `via` 是怎么开始听的（look 看着它 / wake 唤醒词 / follow 接着说），`seconds` 是说了多久，`looked` 是说话时看着它的比例。
- `reason`：`SHORT` 太短、`NOT FACING` 没看着、`FILLER` 语气词、`ECHO` 回声、`NOT FOR ME` 大模型判断不是对它说的、`EMPTY` 没识别出内容。
- 用几天以后把这个文件发给我，就能按真实情况调 `listen` 里的参数，比如被冤枉不理的多，就放宽；误触发的多，就收紧。

**大模型的四个新技能**：`move`（forward / backward / left / right，0.05–3 米）、`turn`（正数左转）、`stop`、`posture`（stand / fold）。
- 边说边走：说完话就回到待机，**走的时候照样能听**，说“停”或摸头马上刹住。

- 没有地图、不会跟人、不会自己找路——让它“去厨房”它会说做不到，问你方向和距离。

**感觉板上新多的**：底盘状态（趴着 / 站着 / 急停……）、移动速度、从开机算起走到的位置（轮子算的，有误差）、背上货物重量（走一趟就估出来，±1.5 kg）、电池电量。
屏幕下面那条的 `SPD`、`LOAD` 和右上角电量现在是真数（虚拟底盘时是仿真的数）；数据流里每 4 秒推一行 `BASE STAND V+0.40 X+1.23 Y+0.00 H+90`。
底盘的提醒和故障：急停 → 屏幕 ALERT `E-STOP`；髋卡住等故障 → ERROR；电量低 → LOW BAT；都记进事件日志。

底盘程序本身（运动学、加减速、急停、断线自停、站起来趴下、载重估计）在 `007v/chassis/`，说明见 `docs/机械狗007v/底盘程序说明.md`。
